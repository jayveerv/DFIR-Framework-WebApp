8. Method and limitations

Evidence was acquired read-only and copied with SHA-256 verification; every format was normalised into one UTC event schema; detection used the CP-DFIR rule set mapped to MITRE ATT&CK; events were linked into incidents through shared entities (attacker IP address, credential file, cloud access key); every step was recorded in an HMAC-signed, hash-chained custody ledger. Findings are leads for the investigator to confirm, not automatic conclusions.

  • Detection is rule-based; thresholds are in config.py.
  • Linux session attribution assumes a command belongs to the latest login of the same user on the same host (auth.log has no session id for sudo).
  • The credential link uses the analyst-supplied credential_inventory in case_config.json; the logs alone do not show which key is stored in a file.
  • “Internal” addresses are private ranges plus internal_ranges in the case config.
